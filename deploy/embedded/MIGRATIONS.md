# Embedded release and migration notes

This document is the operator record for the embedded relay release lane.
Embedded SQLite is fresh-install-only when migrating from PostgreSQL: there is
no supported PostgreSQL-to-SQLite import. An existing distributed deployment
stays on PostgreSQL/Redis/S3.

## SQLite upgrade contract

Upgrades between supported embedded releases use the checked-in SQLite SQLx
migrations under `migrations/sqlite/`. The relay applies pending migrations
before readiness is reported and records each successful version exactly once;
a failed migration must leave readiness unhealthy rather than serving a
partially upgraded schema.

Before every upgrade:

1. Stop the relay cleanly so no writer owns `/data/buzz.sqlite3`.
2. Copy the complete `/data` directory, including `secrets/`, SQLite WAL/SHM
   files, and filesystem media.
3. Record the old image digest and verify the backup is readable.
4. Start the new immutable image with the same `/data` volume.
5. Wait for `/_readiness`, then verify the relay identity and a representative
   message/media read before reconnecting clients.

Rollback is a restore operation, not a binary downgrade: stop the new relay,
replace `/data` with the pre-upgrade backup, and restart the old image. Never
run an older binary against a schema after a newer migration has committed.

## Release evidence

For a candidate `relay-vX.Y.Z`, record all of the following in the release
change:

- the tag commit and image digest;
- the SQLite migration versions present in that image;
- the result of the embedded compose startup/restart/backup smoke test;
- the measured SQLite scaling profile and known capacity boundary;
- the SBOM generated by the Docker build (`sbom: true`); and
- the provenance verification command:
  `gh attestation verify oci://ghcr.io/chesapeakedev/buzz:<tag> --owner chesapeakedev`.

The Docker workflow is the authority for image publication, SBOM generation,
and provenance attestation. A local build or a rolling `:main` image is not a
stable release and must not be described as one.
